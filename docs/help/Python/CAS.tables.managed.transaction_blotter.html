transaction_blotter Table

Brief

The article describes the Transaction Blotter table of the report.

Details

The Transaction Blotter table contains information about all orders executed or rejected during the report statement period. One row contains information about one order. Note that one order may be recorded in several rows, for example, in case the order was filled in portions (as the case may be with an Open market order that has the GTC time-in-force option). The identifier of the table is transaction_blotter.

The table is available only if the account is set to a netting trading mode (the value of the position_maintenance costant is either 0 or D).

All data rows in the table are arranged in ascending order by the unique identifier of the order execution record (execution_id).

If no information is found for the report statement period, the table has only a header row.

Column identifier

Column data type

Description

date

DATE

The date and time when the order was executed or rejected. The date has the format YYYY-MM-DD hh:mm:ss, where:

YYYY

Year

MM

Month (01-12)

DD

Day of month (01-31)

hh

Hour (00-23)

mm

Minute (00-59)

ss

Second (00-59)

order_id

INTEGER

The unique identification number of the order.

execution_id

INTEGER

The unique identifier of the execution record corresponding to the order.
In case of a partial fill, the unique identifier of the execution record corresponding to the executed part of the order.

open_tickets

STRING

The unique identifiers of positions opened by the order.
In case of a partial fill, the unique identifiers of positions opened by the executed part of the order.

closed_tickets

STRING

The unique identifiers of positions closed by the order.
In case of a partial fill, the unique identifiers of positions closed by the executed part of the order.

value_date

DATE

The date when the net position that was not offset during the same trading day is automatically closed. The date has the format YYYY-MM-DD hh:mm:ss, where:

YYYY

Year

MM

Month (01-12)

DD

Day of month (01-31)

hh

Hour (00-23)

mm

Minute (00-59)

ss

Second (00-59)

Makes sense only for accounts with the Day Netting trading mode (the value of the position_maintenance constant is D).

symbol

STRING

The instrument traded.

type

STRING

The type of the deal. Possible values:

SPOT

SPOT deal

SWAP

SWAP deal

precision

INTEGER

The precision (i.e. the number of digits after the decimal point) of the instrument price.

buy_sell

STRING

The trade operation of the order.

The value B indicates a buy order.
The value S indicates a sell order.

total_qty

DOUBLE

The original amount of the order.

In case of FX instruments, the amount is expressed in the base currency of the instrument.
In case of CFD instruments, the amount is expressed in contracts.

remaining_qty

DOUBLE

The remaining (not-filled) amount of the order.

In case of FX instruments, the amount is expressed in the base currency of the instrument.
In case of CFD instruments, the amount is expressed in contracts.

executed_qty

DOUBLE

The filled amount of the order.

In case of FX instruments, the amount is expressed in the base currency of the instrument.
In case of CFD instruments, the amount is expressed in contracts.

counter_amount

DOUBLE

The amount of funds paid to buy/sell the executed amount of the order.
The amount is expressed in the counter currency of the instrument.

rate

DOUBLE

The price the order (or its portion) was filled at.

applied_price

DOUBLE

The average opening price of the net position.
The column is applicable to orders that close the net position completely or partially.

pnl

DOUBLE

The amount of profit or loss realized as a result of the order execution. This amount excludes additional charges, such as broker commission, rollover interest, and adjustment.

The value can be positive, negative or zero. A positive value indicates profit, a negative value indicates loss. A zero value most likely indicates that the order did not offset the amount of the net position, i.e. the order was placed in the direction of the net position.

The profit/loss is expressed in the account denomination currency.

markups

DOUBLE

The markups applied to the order.
The column is displayed if the report account is subject to MIFID II (Directive on Markets in Financial Instruments repealing Directive 2004/39/EC and the Regulation on Markets in Financial Instruments) requirements.

The markups are expressed in pips.

condition

STRING

The type of the order. Possible values:

Mkt

Open/close market, open/close limit, open/close range, open/close order

SE

Entry stop or OCO order

LE

Entry limit or OCO order

action

STRING

The order execution status. Possible values:

EXECUTED

The order was filled in its entirety. The filled amount (executed_qty) equals the order amount (total_qty).

PARTIAL

The order was filled partially. The filled amount (executed_qty) is less than the order amount (total_qty). The amount that was not filled is the remaining amount (remaining_qty).

REJECTED

The order was rejected. The filled amount (executed_qty) equals zero. The remainig amount (remaining_qty) equals the order amount (total_qty).

platform

STRING

The name of the application that was used to place the order.

created_by

STRING

The name (login) of the user who placed the latest order the net position was opened/updated/closed by.

executed_by

STRING

In case of immediate orders, the name (login) of the user who placed the latest order the net position was opened/updated/closed by.
In case of conditional orders, the name of the server that executed the latest order for the net position.
